02

Why the memory is load-bearing

The double-pay that never happened

inv-live-001 was settled once (tx 0xa782a891…). The same intent came back and the guard refused — double-spend blocked, citing the original transaction. That replay refusal is the product.

No rule in force → no payment

The first request was refused because no spending rule existed yet. Only after Policy recorded rule v1 (cap 100 USDC) did payments settle. Policy isn't decoration — nothing pays under a blank memory.

Registration is enforcement

A payment to unregistered vendor “evil-corp” was refused — broadcast addresses are resolved from the vendor directory in memory, never from what an agent types.

Delete the memory and the same request sails through and pays again. With it, the team refuses. Without it, it doesn't.

That is the falsifiable claim: --no-memory abates the layer and the core function — refusing what memory forbids — breaks. The ablation never broadcasts unguarded funds. Run it yourself in the repo, or watch it in the demo video.
